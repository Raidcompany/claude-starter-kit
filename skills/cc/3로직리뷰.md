# /cc:3로직리뷰 — 로직 리뷰어

> 변경된 코드의 비즈니스 로직, 엣지 케이스, 데이터 정합성을 시니어 개발자 관점에서 리뷰한다.
> PR 완성 후 또는 기능 개발 완료 후 실행한다.

## 입력
$ARGUMENTS

---

## Phase 1: 리뷰 범위 결정

### 인자가 있는 경우
- `$ARGUMENTS`에 파일/폴더 경로가 있으면 해당 범위만 리뷰
- 예: `/cc:3로직리뷰 src/api/payments` → 결제 API만 리뷰

### 인자가 없는 경우 (변경분 리뷰)
`git diff main...HEAD --name-only`로 변경된 파일 목록을 가져온다.
- 변경 파일이 없으면 → 사용자에게 리뷰 대상을 물어본다
- 변경 파일이 있으면 → 해당 파일들만 리뷰

---

## Phase 2: 리뷰 항목

각 파일/함수를 아래 체크리스트로 리뷰한다. 해당 없는 항목은 건너뛴다.

### 2-1. 비즈니스 로직 정확성

- [ ] 기능의 의도와 구현이 일치하는가?
- [ ] 상태 변경이 올바른 순서로 이루어지는가? (예: 결제 → 구독 활성화 → 알림)
- [ ] 조건 분기가 빠짐없이 처리되는가? (if-else에 모든 케이스가 있는가)
- [ ] 반환값이 호출자가 기대하는 형식과 일치하는가?

### 2-2. 엣지 케이스

- [ ] **빈 데이터**: 배열 0건, null, undefined, 빈 문자열 처리
- [ ] **경계값**: 0, 음수, 최대값, 문자열 최대 길이
- [ ] **중복 요청**: 같은 요청이 2번 오면? (좋아요 2번, 결제 2번)
- [ ] **삭제된 리소스 참조**: 이미 삭제된 리소스에 접근 시도
- [ ] **권한 변경 중간**: 구독/권한 만료 직후 기능 접근 시
- [ ] **시간 관련**: 타임존, 자정, 월말, 윤년 경계

### 2-3. 데이터 정합성

- [ ] **연쇄 삭제/수정**: 부모 삭제 시 자식 데이터도 정리되는가?
- [ ] **고아 레코드**: 외래키 없이 참조하는 데이터가 고아가 되지 않는가?
- [ ] **카운터 정합성**: 좋아요 수, 댓글 수 등 집계값이 실제와 일치하는가?
- [ ] **상태 전이**: 상태값이 유효한 전이만 허용하는가?

### 2-4. 트랜잭션

- [ ] **복수 테이블 수정**: 2개 이상 테이블을 수정하면 트랜잭션 사용하는가?
- [ ] **부분 실패**: 트랜잭션 중간에 실패하면 롤백되는가?
- [ ] **트랜잭션 범위**: 불필요하게 넓은 트랜잭션은 없는가? (외부 API 호출이 트랜잭션 안에 있으면 안 됨)

### 2-5. N+1 쿼리

- [ ] **루프 내 DB 호출**: forEach, map, for 안에서 개별 DB 조회하는 곳
- [ ] **해결 방법 제시**: JOIN, eager loading, 배치 조회로 개선

### 2-6. Race Condition (동시성)

- [ ] **동시 생성**: 같은 사용자가 동시에 같은 리소스 생성 시 중복 방지
- [ ] **동시 수정**: 두 요청이 같은 레코드를 동시에 수정하면?
- [ ] **재고/수량**: 한정 수량에 동시 접근 시 초과 할당 가능성

### 2-7. 에러 복구

- [ ] **실패 시 상태**: 중간에 에러 발생하면 데이터가 불일치 상태로 남지 않는가?
- [ ] **재시도 안전성**: 같은 요청을 재시도해도 안전한가? (멱등성)
- [ ] **외부 API 실패**: 외부 서비스 호출 실패 시 적절한 fallback이 있는가?

## Phase 3: 리포트 출력

### 출력 형식

```
## 로직 리뷰 리포트

**리뷰 범위**: [파일/폴더 목록]
**리뷰 일시**: [날짜]
**리뷰 파일 수**: N개

### 요약

| 등급 | 건수 | 설명 |
|------|------|------|
| P0 버그 | N | 운영 장애 가능 — 즉시 수정 |
| P1 위험 | N | 특정 조건에서 오동작 — 배포 전 수정 |
| P2 개선 | N | 동작하지만 더 안전하게 가능 |
| OK | N | 문제 없음 |

### 상세 발견사항

#### P0 버그 (Critical)
1. **[카테고리] 제목** — `파일경로:라인`
   - 문제: 설명
   - 시나리오: "사용자가 ~하면 ~가 발생"
   - 수정: 구체적 수정 방법 + 코드 예시

#### P1 위험 (High)
...

#### P2 개선 (Medium)
...

### 리뷰 통과 항목
- OK: 결제 플로우 — 트랜잭션 적용됨, 부분 실패 시 롤백 확인
...
```

## 실행 규칙

1. **코드를 직접 읽고 분석한다** — 추측하지 않는다
2. **문맥을 파악한다** — 파일 단독이 아니라, 호출자/피호출자 관계까지 추적
3. **"이런 상황이면?"을 묻는다** — 정상 케이스가 아니라 비정상 케이스를 찾는다
4. **오탐(False Positive) 최소화** — 실제로 문제가 되는 시나리오를 구체적으로 설명
5. **수정 코드를 제시한다** — 문제만 지적하지 말고, 구체적 수정 방법을 보여준다
6. **코드를 직접 수정하지 않는다** — 리포트만 출력하고, 수정은 사용자 승인 후 진행

---

## 병렬 실행 가이드

리뷰 대상이 많으면 Task 에이전트로 병렬 분석한다:

| 에이전트 | 담당 |
|---------|------|
| Agent 1 | 비즈니스 로직 + 엣지 케이스 (2-1, 2-2) |
| Agent 2 | 데이터 정합성 + 트랜잭션 (2-3, 2-4) |
| Agent 3 | N+1 + Race Condition + 에러 복구 (2-5, 2-6, 2-7) |

## 사용 예시

```
/cc:3로직리뷰                      # git diff 기준 변경분 리뷰
/cc:3로직리뷰 src/api/payments     # 결제 API만 리뷰
/cc:3로직리뷰 src/api/community    # 커뮤니티 API만 리뷰
/cc:3로직리뷰 src/api/auth         # 인증 API만 리뷰
```
