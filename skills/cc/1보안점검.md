# /cc:1보안점검 — 보안점검 스캐너

> 프로젝트 코드를 OWASP/CWE 기준으로 점검하고, 취약점을 찾아 리포트한다.

## 입력
$ARGUMENTS

---

## Phase 1: 점검 범위 결정

### 인자가 있는 경우
- `$ARGUMENTS`에 파일/폴더 경로가 있으면 해당 범위만 점검
- 예: `/cc:1보안점검 src/api/auth` → 인증 API만 점검

### 인자가 없는 경우 (전체 점검)
아래 보안 민감 영역을 자동 탐색:
1. **API/라우트**: 서버사이드 엔드포인트 전체
2. **인증/미들웨어**: auth, middleware, session 관련 파일
3. **DB 접근**: ORM 설정, 쿼리 헬퍼, 마이그레이션
4. **보안 유틸**: rate limiter, CORS, CSRF 관련
5. **인프라**: Docker, Nginx, 서버 설정 파일
6. **프론트 HTML 렌더링**: raw HTML 삽입하는 컴포넌트

---

## Phase 2: 점검 항목 (CWE 기반)

각 파일을 아래 체크리스트로 점검한다. 해당 없는 항목은 건너뛴다.

### SQL Injection (CWE-89)
- [ ] Raw SQL에 사용자 입력이 문자열 결합으로 들어가는지
- [ ] ORM의 unsafe raw query 메서드 사용 여부
- [ ] 파라미터 바인딩 없이 쿼리를 조립하는 곳

### XSS (CWE-79)
- [ ] Raw HTML 삽입 시 sanitize 적용 여부 (dangerouslySetInnerHTML, v-html, innerHTML 등)
- [ ] 사용자 입력이 직접 DOM에 삽입되는 곳
- [ ] 템플릿 엔진에서 이스케이핑이 비활성화된 곳

### 입력 검증 (CWE-20)
- [ ] POST/PUT/PATCH API에 서버사이드 입력 검증이 있는지
- [ ] 쿼리 파라미터 검증이 있는지
- [ ] 숫자/ID 파라미터의 타입 체크

### 접근 제어 (CWE-284)
- [ ] 인증 필요 API에 세션/토큰 체크가 있는지
- [ ] 관리자 전용 API에 권한 검증이 있는지
- [ ] 리소스 접근 시 본인 소유 확인 (IDOR 방지)

### SSRF (CWE-918)
- [ ] 사용자 제공 URL로 서버사이드 fetch하는 곳
- [ ] 내부 IP 대역(127.0.0.1, 10.x, 172.16.x, 192.168.x) 차단 여부

### Rate Limiting (CWE-400)
- [ ] 쓰기 API에 Rate Limit 적용 여부
- [ ] 인증 API에 엄격한 제한 여부
- [ ] DB 쿼리에 LIMIT 적용 여부

### 시크릿/자격증명 (CWE-798)
- [ ] 하드코딩된 API 키, 비밀번호, 시크릿 없는지
- [ ] `.env` 파일이 gitignore에 포함되어 있는지

### 에러 처리
- [ ] catch 블록에서 내부 정보(stack trace, DB 쿼리)를 응답에 노출하지 않는지
- [ ] 사용자에게는 일반적인 에러 메시지만 반환하는지

### 암호화 (CWE-311)
- [ ] 비밀번호가 안전한 해시(bcrypt/argon2 등)로 저장되는지
- [ ] `Math.random()` 등 비보안 난수가 토큰 생성에 사용되지 않는지

### CSRF (CWE-352)
- [ ] 쿠키에 SameSite, Secure, HttpOnly 설정 여부

### Prototype Pollution
- [ ] 사용자 입력을 Object spread로 직접 처리하는 곳
- [ ] `__proto__`, `constructor` 필터링 여부

### 인프라
- [ ] 보안 헤더 설정 (X-Frame-Options, HSTS, X-Content-Type-Options)
- [ ] CORS 설정 적절한지
- [ ] 불필요한 포트/서비스 노출

### 요약

| 등급 | 건수 | 설명 |
|------|------|------|

| ⚠️ 경고 | N | 조기 수정 권장 |
| ℹ️ 참고 | N | 개선하면 좋음 |

1. **[CWE-XXX] 제목** — `파일경로:라인`
   - 문제: 설명
   - 수정: 구체적 수정 방법

#### ⚠️ 경고 (Warning)
...

#### ℹ️ 참고 (Info)
...

### 점검 통과 항목
- ✅ SQL Injection: ORM 사용, Raw 쿼리 없음

## 실행 규칙

1. **코드를 직접 읽고 분석한다** — 추측하지 않는다
2. **오탐(False Positive) 최소화** — 확실한 취약점만 위험/경고로 분류
3. **수정 코드를 제시한다** — 문제만 지적하지 말고, 구체적 수정 방법을 보여준다
4. **코드를 직접 수정하지 않는다** — 리포트만 출력하고, 수정은 사용자 승인 후 진행
5. **프로젝트의 코딩 규칙(CLAUDE.md 등)이 있으면 함께 기준으로 사용한다**
