# /cc:머지 — 병렬작업 머지 매니저

> 병렬 작업자들의 보고서를 확인하고, 코드 충돌을 분석한 뒤, 안전하게 머지한다.

## 입력
$ARGUMENTS

→ 세션 폴더명을 입력받는다. 예: `0215_채널분석성능개선`
→ 입력이 없으면 `~/.cc-parallel/` 내 가장 최근 폴더를 자동 선택한다.

---

## Phase 1: 변경사항 분석 (코드 기반)

> **원칙**: 실제 코드 변경이 진실의 원천이다. 보고서는 참고용일 뿐, 없어도 머지를 진행한다.

### 1-1. 코드 변경 분석 (필수)
```bash
git status
git diff --stat
git diff          # 실제 변경 내용 확인
```

### 1-2. 지시서 대조 (필수)
`~/.cc-parallel/[세션폴더]/` 내 작업자 지시서(`*_[역할].md`)를 읽고, 지시된 작업 vs 실제 변경을 대조한다.

### 1-3. 보고서 참고 (선택)
`*_보고서.md` 파일이 있으면 읽어서 추가 정보(주의사항, 미완료 사유 등)를 참고한다.
- 보고서 있음 → 주의사항/미완료 정보 활용
- 보고서 없음 → 코드 + 지시서 대조만으로 진행
- 보고서 양식 틀림 → 무시하고 코드 기반으로 진행

### 1-4. 분석 결과 출력

```
## 변경사항 분석

### 변경 요약
- 변경 파일: N개 (+N줄 / -N줄)
- 작업자별: A(N파일), B(N파일), C(N파일)

### 충돌
- [있음/없음] [상세 내용]

### 품질 이슈
- [있음/없음] [상세 내용]

### 지시서 대비 누락
- [있음/없음] [상세 내용]

### 보고서 참고사항
- [보고서 있으면 주의사항 표시, 없으면 "보고서 없음 — 코드 기반 분석"]
```

## Phase 2: 판단 및 실행

### Case 1: 문제 없음 → 빌드 검증 후 머지
```
✅ 충돌 없음, 품질 이슈 없음

빌드 검증을 실행합니다...
```

1. 빌드 실행 — **이 단계가 전체 워크플로우의 유일한 빌드 검증 포인트**
2. 빌드 성공 → `git add` + `git commit`
3. 빌드 실패 → 에러 분석 후 Case 2 또는 Case 3으로 분기

### Case 2: 경미한 이슈 → 자동 수정 후 머지
```
⚠️ 경미한 이슈 발견 — 자동 수정 가능

수정 내용:
- [파일]: [수정 내용]

수정 후 빌드 재검증합니다.
```

- 사소한 타입 불일치, 미사용 import, 빌드 에러 등은 자동 수정
- 수정 후 빌드 재실행하여 검증
- 빌드 성공 확인 후 커밋

### Case 3: 심각한 이슈 → 사용자 판단 요청
```
🚨 머지 불가 — 사용자 확인 필요

문제:
1. [파일충돌] 작업자A와 B가 같은 파일 수정
   - A: [변경 내용]
   - B: [변경 내용]
   → 어느 쪽을 살릴까요?

2. [미완료] 작업자B의 작업 1개 미완료
   → 무시하고 머지? / 재작업 지시서 생성?
```

### Case 4: 재작업 필요 → 추가 지시서 생성
```
📝 재작업 지시서 생성

~/.cc-parallel/[세션폴더]/재작업_작업자B.md 생성 완료
→ 해당 프롬프트에 복붙하세요
```

## Phase 3: 회고 기록

머지 완료 후 (성공/실패 무관) 학습 기록을 남긴다:

### `~/.cc-parallel/[세션폴더]/회고.md` 생성

```markdown
# 회고: [세션명]
# 날짜: [YYYY-MM-DD HH:MM]

## 결과
- 상태: 성공 / 부분성공 / 실패
- 작업자 수: [N]명
- 소요시간: [추정]

## 잘된 점
- [잘된 것]

## 개선할 점
- [개선할 것]

## 다음에 적용할 것
- [학습 내용]
```

## 동작 요약

```
/cc:머지 [세션폴더명]
    │
    ├─ Phase 1: 변경사항 분석
    │   ├─ git diff (필수) — 코드가 진실의 원천
    │   ├─ 지시서 대조 (필수) — 누락 작업 확인
    │   └─ 보고서 참고 (선택) — 있으면 활용, 없어도 진행
    │
    ├─ Phase 2: 판단
    │   ├─ 문제 없음 → 빌드 → 성공 → 커밋
    │   ├─ 경미한 이슈 → 자동 수정 → 빌드 → 커밋
    │   ├─ 심각한 이슈 → 사용자 판단 요청
    │   └─ 재작업 필요 → 추가 지시서 생성
    │
    └─ Phase 3: 회고 기록
```

---

## 사용 예시

```
/cc:머지                           # 가장 최근 세션 자동 선택
/cc:머지 0215_채널분석성능개선       # 특정 세션 지정
```
