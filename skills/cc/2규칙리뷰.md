# /cc:2규칙리뷰 — 코드 규칙 점검

> 프로젝트 코드를 CLAUDE.md 코드 표준 패턴 + 린터 규칙 기준으로 점검한다.
> AI가 작성한 코드가 프로젝트 규격에 맞는지 확인하는 1차 리뷰.

## 입력
$ARGUMENTS

---

## Phase 1: 점검 범위 결정

### 인자가 있는 경우
- `$ARGUMENTS`에 파일/폴더 경로가 있으면 해당 범위만 점검
- 예: `/cc:2규칙리뷰 src/api/channels` → 채널 API만 점검

### 인자가 없는 경우 (전체 점검)
아래 영역을 자동 탐색:
1. **API/라우트**: 서버사이드 엔드포인트
2. **컴포넌트**: UI 컴포넌트
3. **라이브러리**: 유틸리티, 헬퍼
4. **커스텀 훅**: 상태 관리 훅
5. **타입 정의**: 타입/인터페이스
6. **스토어**: 상태 관리

---

## Phase 2: 점검 항목

> **기준 문서**: 프로젝트의 CLAUDE.md (코드 표준 패턴 섹션) + 린터 설정

### 2-1. API Route 표준 패턴

- [ ] **순서**: 인증 → 입력 검증 → 비즈니스 로직 → 통일 응답
- [ ] **인증**: 세션/토큰 체크가 최상단에 있는가
- [ ] **입력 검증**: 서버사이드 검증 라이브러리 사용하는가 (Zod, Joi 등)
- [ ] **응답 형식**: 프로젝트 표준 응답 형식을 따르는가
- [ ] **에러 처리**: 공통 에러 핸들러를 사용하는가
- [ ] **직접 console.error 사용 금지**: 공통 핸들러로 위임

### 2-2. HTTP 상태코드

- [ ] 400: 입력 검증 실패, 비즈니스 로직 오류
- [ ] 401: 인증 필요
- [ ] 403: 권한 부족
- [ ] 404: 리소스 없음
- [ ] 429: Rate Limit 초과

### 2-3. 페이지네이션

- [ ] 목록 API에 표준 페이지네이션 패턴 사용하는가
- [ ] page/size 파라미터 검증
- [ ] 응답에 페이지 메타데이터 포함

### 2-4. Rate Limiter

- [ ] **필수**: 인증 API, 결제 API, AI/외부 API 호출
- [ ] **권장**: 데이터 생성 POST
- [ ] 표준 패턴 사용

### 2-5. DB 접근 패턴

- [ ] ORM import 경로가 프로젝트 표준을 따르는가
- [ ] Unsafe raw query 메서드 사용 금지
- [ ] Raw 쿼리: 파라미터 바인딩 방식만 허용
- [ ] 목록 조회에 LIMIT 포함 (예외: 배열 크기 제한, 설정 테이블 등)

### 2-6. 보안 코딩

- [ ] 시크릿 하드코딩 금지 — 환경변수 사용
- [ ] `eval()`, 동적 코드 실행 함수 사용 금지
- [ ] Raw HTML 삽입 시 sanitize 적용
- [ ] 보안 난수 생성기 사용
- [ ] 에러 응답에 내부 정보 노출 금지
- [ ] 외부 링크에 `rel="noopener noreferrer"`
- [ ] 비밀번호 안전한 해시

### 2-7. 프론트엔드 패턴

- [ ] Server/Client 컴포넌트 구분이 프로젝트 패턴을 따르는가
- [ ] 모바일 반응형 (mobile-first)
- [ ] 프로젝트 표준 UI 라이브러리 사용

### 2-8. Import/Export 일관성

- [ ] import 경로 별칭(alias) 사용 일관성
- [ ] 타입 import 위치 일관성
- [ ] 네이밍 컨벤션 일관성

## Phase 3: 점검 실행

### 병렬 에이전트 구성

점검 대상이 많으면 Task 에이전트로 병렬 분석한다:

| 에이전트 | 담당 |
|---------|------|
| Agent 1 | API Route 패턴 + 상태코드 + 페이지네이션 (2-1, 2-2, 2-3) |
| Agent 2 | Rate Limiter + DB 접근 패턴 (2-4, 2-5) |
| Agent 3 | 보안 코딩 + 프론트엔드 + Import (2-6, 2-7, 2-8) |

### 린터 자동 검사

점검 시작 시 프로젝트 린터를 실행하여 기계적으로 잡을 수 있는 위반을 먼저 확인:

```bash
# 프로젝트에 맞는 린터 실행 (예시)
npx eslint [대상경로] --quiet
# 또는
npx next lint --quiet [대상경로]
```

## 실행 규칙

1. **프로젝트 CLAUDE.md의 코드 표준이 절대 기준이다** — 규칙에 없는 것은 지적하지 않는다
2. **린터 먼저 실행한다** — 기계적 위반은 린터로 빠르게 확인
3. **코드를 직접 읽는다** — 추측하지 않는다
4. **오탐 최소화** — 프로젝트 규칙에 명시된 예외 조건을 반드시 확인
5. **점수를 산출한다** — 이전 점검 결과와 비교할 수 있도록 정량 평가
6. **코드를 직접 수정하지 않는다** — 리포트만 출력, 수정은 사용자 승인 후
