# Git Workflow Rules

## Branch Strategy

```
main (배포용 — 직접 작업 금지)
└── dev/{name}     ← 각 개발자 전용 브랜치
    └── feature/*  ← 기능 브랜치 (선택)
```

- **main에서 직접 작업 금지** — 항상 작업 브랜치에서 작업 후 merge
- **force push 금지** — 특히 main/master

## Commit Convention

```
[카테고리 - 설명]

예시:
[기능 개발 - 로그인 페이지 추가]
[오류 - 회원가입 시 404 에러 수정]
[개선 - 검색 성능 최적화]
[리팩토링 - API 에러 핸들링 통합]
```

| 카테고리 | 용도 |
|---------|------|
| 기능 개발 | 새 기능 추가 |
| 오류 | 버그 수정 |
| 개선 | 기존 기능 향상 |
| 리팩토링 | 기능 변경 없이 코드 개선 |
| 문서 | 문서 추가/수정 |
| 설정 | 빌드/배포/환경 설정 |

## Session Start Checklist

1. `git status` — 현재 상태 확인
2. `git branch` — 올바른 브랜치인지 확인
3. main이면 **작업 시작 금지** → 작업 브랜치로 이동

## Best Practices

- 커밋 전 반드시 `git diff`로 변경 내용 확인
- 위험한 작업 전 커밋 (복구 지점 생성)
- 실험은 별도 브랜치에서
- 100줄 이상 변경 시 변경 요약 먼저 제시
- 파일 삭제 전 반드시 확인 요청
