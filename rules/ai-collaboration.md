# AI Collaboration Rules

> Claude Code(AI)와 협업할 때 오류를 줄이는 실전 규칙.
> 실제 프로젝트에서 반복 발생한 실수 패턴을 분석해서 만들었다.

## AI가 자주 저지르는 실수 TOP 4

| 실수 | 구체적 예시 | 방지법 |
|------|-----------|--------|
| 기존 코드 안 읽고 추측 | 이미 있는 함수를 다르게 다시 만듦 | 관련 파일 전부 읽고 시작 |
| DB 스키마 가정 | `createdAt` 추측 → 실제는 `created_at` | ORM 스키마에서 실제 컬럼명 확인 |
| 빌드 안 돌리고 완료 선언 | 타입 에러 10개 남아있음 | 파일 3개+ 수정마다 빌드 |
| 프론트↔백 타입 불일치 | API는 `channelId`, 프론트는 `channel_id` | API 타입 먼저 합의 후 양쪽 구현 |

## 핵심 4원칙

### 1. 작게 나눈다
- 한 번에 변경하는 파일 **10개 이하**
- 넘으면 작업을 분할
- 작을수록 리뷰하기 쉽고, 문제 발생 시 원인 추적이 빠름

### 2. 빌드 자주 돌린다
- 파일 **3개 이상** 수정하면 반드시 `npm run build` (또는 프로젝트 빌드 명령)
- "완료"라고 하기 전에 빌드 통과 확인
- 타입 에러는 빌드에서 가장 많이 잡힘

### 3. 의도 먼저 확인
- 코드 쓰기 **전에** "이렇게 만들 건데 맞죠?" 자연어로 확인
- 잘못된 방향으로 100줄 쓰는 것보다, 확인 한 번이 빠름
- 특히 Medium 이상 작업에서 필수

### 4. 기존 코드 먼저 읽는다
- 관련 타입, API, 컴포넌트, DB 스키마를 **먼저 읽고** 구현
- 추측하지 않는다 — 모르면 물어본다
- "이미 비슷한 게 있는지" 항상 확인

## 작업 크기별 프로세스

| 크기 | 기준 | 프로세스 |
|------|------|---------|
| **Small** | 파일 1~3개 | 바로 구현 → 빌드 확인 |
| **Medium** | 파일 4~10개 | 의도 확인 → 구현 → 빌드 확인 |
| **Large** | 파일 10개+ | 의도 확인 → 조사(별도 세션) → 확인 → 구현(작은 단위) → 빌드 확인 |

### Large 작업 시 세션 분리

AI는 컨텍스트가 길어지면 품질이 떨어진다. Large 작업은 세션을 나눈다:

- **조사 세션**: 코드만 읽고 보고서 작성 (수정 없음)
- **구현 세션**: 보고서 참고해서 작은 단위로 구현 (각각 빌드 확인)
- **검증 세션**: 깨끗한 세션에서 빌드 + 동작 확인

## 하지 말 것

- 기존 코드 안 읽고 추측으로 구현
- 한 세션에서 파일 20개 이상 읽고 동시에 수정
- 빌드 안 돌려보고 "완료" 선언
- 프론트와 백엔드 타입을 따로따로 정의 (API 타입을 먼저 합의)
- 모든 작업에 동일한 프로세스 적용 (크기별로 다르게)
